## 使用者、工作與情境

主要使用者：想把時間看得見、不想輸入時間數字的人，首發為台灣使用者，在桌機瀏覽器上看到 Juicy 的網站（對應 G-06、G-01）。目前卡在：Juicy Calendar 只有 GitHub 原始碼庫與英文 README，一般人沒辦法在安裝前知道它用起來如何。（此痛點只有擁有者的陳述與 README 觀察，見 Brief A-01、A-02。）

主流程：進入首頁 → 先看到試用區（從示範日（今天）起連續三天、每天可見 10:00–15:00）→ 選一顆球、拖到日曆、調整長度、雙擊命名 → 看到命名好的區塊 → 往下看到下載區 → 點「下載 Windows 版」。

主要失敗與取消：球拖到日曆外放開、或拖曳中按 Escape，不建立區塊。其餘操作的規則（磁吸、最小長度、超出可見範圍、命名被拒絕時的處理）一律依 Calendar，網站不另訂，也不另外顯示拒絕訊息。試用內容不上傳，也不保存：重新整理頁面，試用內容就消失，日曆回到空的狀態。

## 故事與驗收條件

每條 AC 只驗一項可判斷的承諾，不混合無關需求。**日曆操作的詳細規則不在 AC 裡重述**，以 SRS 沿用登記表為準。已撤回的 AC 保留編號與說明，編號不重用。

### US-01 不安裝，先在網頁上試用排時間（G-06）

身為想把時間看得見的訪客，我想在網頁上直接拖曳色球排時間、調整、移動與刪除區塊，以便不必先安裝，就知道它用起來如何。

- **AC-01.1（成功，畫面回饋）**：Given 訪客在可互動的環境（見 AC-01.6）開啟首頁，試用區可見，側邊有三顆種子球（專注／藍、休息／綠、雜事／橘，中文版名稱中英並列、英文版純英文），日曆為連續三天、空，每天可見範圍 10:00–15:00，磁吸與縮放為 App 預設（磁吸開啟、每分鐘 1 像素；網站不開放這兩項設定） When 把一顆球拖到指標離 10:30 刻度線**垂直距離 8 像素（含）以內**的位置放開，再把該區塊的下緣拖到下緣離 13:00 刻度線 8 像素（含）以內的位置，再雙擊區塊輸入「寫 PRD」並按 Enter Then 示範日出現 10:30–13:00、標題為「寫 PRD」的區塊，顏色與球相同，球仍留在側邊可再次使用，且全程沒有在任何欄位輸入時間數字。（沿用 App 的磁吸規則，來源 SRS REUSE-01，已查原始碼：離最近半點刻度線 ≤ 8 像素 → 吸附到該刻度；> 8 像素 → 不吸附，時間取該位置換算的分鐘數，四捨五入到整分鐘，.5 進位。例：球放在離 10:30 線 8 像素處 → 起點 10:30，區塊 10:30–12:30；放在線上方 9 像素處（第 21 分鐘）→ 起點 10:21，區塊 10:21–12:21；放在線下方 9 像素處 → 起點 10:39。新區塊長度為 120 分鐘，REUSE-02。調整長度時 App 先把指標位置換成整分鐘再判斷磁吸，門檻邊緣可能差約 0.5 分鐘，測試應避開恰好 8 像素的邊界值。）
- **AC-01.2（取消，不產生副作用）**：Given 訪客正在拖曳一顆球 When 在日曆以外的地方放開，或按下 Escape Then 不建立任何區塊，日曆上的區塊數不變。（REUSE-05；Calendar AC-01.2。）
- **AC-01.3（已撤回）**：原「拒絕、不生效並在狀態文字區說明原因」。App 沒有此行為，網站不新增。
- **AC-01.4（不持久、不外送，查看結果）**：Given 訪客在試用區建立了 3 個有標題的區塊 When 重新整理頁面 Then 日曆回到空的狀態、沒有任何區塊，復原歷史也清空，球仍在側邊可用；同一個瀏覽器的另一個分頁不會看到這 3 個區塊（試用資料只屬於目前的分頁，分頁之間不共享）。並且 Given 訪客在試用區建立或修改區塊 When 以瀏覽器開發者工具的網路面板檢查 Then 沒有任何請求攜帶區塊內容（標題、時間），也沒有以 `localStorage` 保存試用內容，且試用區附近有一句說明：試用內容不會上傳，重新整理頁面就會消失。（本條併入原 AC-01.5；編號不重用。）
- **AC-01.6（靜態預覽，不產生副作用）**：Given 訪客的瀏覽器主要輸入不同時符合 `pointer: fine` 與 `hover: hover`（判定只看這兩項，不看裝置名稱、作業系統、螢幕寬度，也不看瀏覽器名稱或版本） When 查看試用區 Then 看不到可操作的試用，改看到一張不能拖曳或點擊的圖片：實際試用介面的截圖，包含三天（每天 10:00–15:00）的日曆、三顆球，以及一個已放好的 10:00–12:00 區塊；圖下文字為「將球拖進日曆，即可建立時間區塊。請使用電腦及滑鼠體驗互動試用。」；圖片標示為產品預覽。圖與說明都有中文與英文兩版，隨網站語言切換，圖片的替代文字與圖下說明同步切換。此環境下不建立區塊、不產生任何資料，且試用模組沒有被載入（網路面板看不到試用模組的請求）；Windows 下載區照常顯示。邊界例子：同一台桌機接滑鼠，把視窗縮到手機寬度，仍然可互動（不看寬度）；只有觸控的手機顯示靜態預覽。（英文版圖下文字尚待定。動態更換輸入裝置見 AC-01.13。）
- **AC-01.7（成功，移動既有區塊）**：Given 日曆上有一個 10:00–12:00 的區塊，在距區塊頂端 20 分鐘處按住（抓取偏移 20 分鐘） When 把指標放開在相對 10:00 為 170 分鐘處（12:50） Then 區塊移到 12:30–14:30，長度仍為 120 分鐘，標題不變。（REUSE-03：新起點 = 指標時間 − 抓取偏移 = 150 分鐘，剛好在 12:30 刻度線上；長度不變。本條只示範算例，不新增磁吸規則，磁吸仍依 REUSE-01。）
- **AC-01.8（已撤回）**：原「先吸附到最近的 30 分鐘刻度再判定」。改為沿用 App 的磁吸（REUSE-01）。
- **AC-01.9（成功，選取與刪除）**：Given 示範日有兩個區塊 When 點選其中一個使它被選取，再按 `Delete` 或 `Backspace`（或用右鍵選單的刪除） Then 被選取的區塊立即消失，沒有確認步驟，另一個區塊不變，可以復原。Given 沒有被選取的區塊 When 按 `Delete` 或 `Backspace` Then 資料不變，也不顯示任何訊息。（REUSE-07；沒有網站專屬的刪除按鈕。）
- **AC-01.10（成功，復原與重做）**：Given 示範日依序完成四個操作：建立區塊 A、把 A 移到較晚的時間、把 A 命名為「寫 PRD」、刪除 A When 連續復原四次 Then 依序回到：A 回來（含移動後的時間與名稱「寫 PRD」）、A 的標題回到命名前的值、A 回到建立時的時間、日曆為空。When 重做一次 Then A 重新出現在建立時的時間。When 復原後又完成一個新的成功操作 Then 重做不能再用。歷史上限 100 步；切換靜態預覽再恢復後歷史保留；重新整理則歷史連同試用資料一起清除。（REUSE-08；每次成功的建立、移動、調整長度、命名、刪除各是一步。）
- **AC-01.11、AC-01.12（已撤回）**：原「鍵盤替代」與「鍵盤操作被拒絕」。App 沒有鍵盤建立、移動、調整長度，網站不新增；可近用限制見 SRS NFR-07。
- **AC-01.13（動態改變輸入能力）**：Given 可互動的試用區，示範日已有 2 個完成的區塊，使用者正在拖曳第三顆球（尚未放開） When 瀏覽器主要輸入變成不符合互動資格（例如拔掉滑鼠） Then 這次拖曳不產生第三個區塊；試用區改為靜態預覽；已完成的 2 個區塊資料與復原歷史仍保留在目前分頁。When 輸入能力恢復符合 Then 回到互動試用，仍看到原本的 2 個區塊，可繼續操作，復原歷史仍在。（正在命名時失去資格不另訂規則，沿用 App 的卸載行為，實際結果待驗證，SRS OR-24。）
- **AC-01.14（已撤回）**：原「狀態訊息的出現與清除」。沒有狀態文字區。
- **AC-01.15（UI 範圍與示範日）**：Given 可互動的試用區 When 查看畫面 Then 日曆為連續三天、每天可見範圍 10:00–15:00（共 15 小時）、第一天是這次初始化時的本地今天；保留的功能有：三顆球、命名、選取與多選（含框選）、刪除、復原／重做、右鍵選單、剪貼簿；不出現：工作區管理與檔案存取，以及日期切換、起訖時間設定、右側編輯面板（這三項暫列排除，相依性待確認，SRS OR-20）。區塊可以延伸到可見範圍之外，網站不新增「必須完整位於範圍內」的限制。過去日降低飽和度的規則維持 App 現狀；測試可注入日期。
- **AC-01.16（與 Calendar 行為一致）**：Given 同一組操作序列（建立、移動、調整長度、命名、刪除、復原） When 在網站試用與在固定版本的 Calendar 共用模組各執行一次 Then 區塊集合、標題與復原歷史的結果相同。（驗證：共用模組在 Calendar 端的測試，加上網站端的整合測試；尚無測試已執行的紀錄。）

### US-02 試用後，能找到並下載 Windows 版，且知道限制（G-01、G-02）

身為試用過的訪客，我想在同一頁找到下載，並先看到系統需求與警告說明，以便安心安裝。

- **AC-02.1（成功，畫面回饋）**：Given 訪客在首頁（macOS、Linux 或 Windows 的瀏覽器看到的下載區相同，都是 Windows 下載），試用區在上、下載區在下 When 捲動到下載區並點「下載 Windows 版」 Then 瀏覽器直接下載 Juicy Calendar GitHub Release 固定版本的 Windows 檔案（專案擁有者 2026-11-11 決定，取代原「前往最新版本頁」）；免安裝 .zip 與原始碼連結也在下載區內；從開啟首頁到開始下載，點擊不超過兩次。
- **AC-02.2（查看結果）**：Given 訪客在下載區 When 閱讀 Then 看到：僅支援 Windows 10 1803 以上 64 位元、需要 WebView2 執行階段、安裝檔未簽章所以 SmartScreen 會警告以及如何繼續、網頁試用為瀏覽器版（與桌面版的差異），以及桌面 App 離線、無帳號；每一項敘述都能對到 Calendar 文件中的來源，沒有未驗證的功能宣稱。
- **AC-02.3（頁尾授權連結）**：Given 訪客在首頁 When 查看頁尾 Then 看到 `LICENSE` 與 `TRADEMARKS.md` 兩個連結（連結文字隨網站語言），點擊後各開啟對應文件。連結指向哪裡取決於 GitHub repo 是否公開與 LICENSE 檔案的落地（Brief D-10），所以本條在公開上線前才能完整驗收。

### US-03 用我的語言看，且不被追蹤（G-03、G-04）

身為台灣的訪客，我想看到繁體中文頁面，並確定網站不會追蹤我，以便放心使用。

- **AC-03.1（成功，畫面回饋）**：Given 訪客沒有手動選過語言，瀏覽器語言為繁體或簡體中文（任何中文地區，例如 zh-TW、zh-HK、zh-CN） When 開啟首頁 Then 顯示繁體中文；瀏覽器語言為不支援的語言（例如 ja）則顯示英文；有多個候選時取第一個（REUSE-12）。當訪客手動切換語言後，**介面文字**（含試用區 App 的介面文字、靜態預覽圖與說明）立即變成所選語言，沒有殘留另一種語言或漏譯；重新整理頁面後，仍維持所選語言，試用資料不因此保留。訪客清除網站資料後，回到依瀏覽器語言決定。**不在此驗收範圍**：使用者資料（區塊標題，包含複製自球名稱的預設標題）與三顆種子球的名稱，它們不隨介面語言翻譯。
- **AC-03.2（隱私，可查詢結果）**：Given 頁面已部署到測試環境 When 檢查頁面載入的網路請求與 cookie Then 沒有跨站追蹤、沒有識別個人的 cookie、沒有廣告請求；頁面上明講「本網站不使用流量統計。」（頁尾，中英文；專案擁有者 2026-11-13 決定不做流量統計，原文要求的「哪種統計、收集什麼」因此改成這一句），並說明桌面 App 本身離線、無遙測。**另外兩點已於 2026-11-14 依專案擁有者要求加上：** 頁尾「網站只在你的瀏覽器保存你選擇的語言，不會上傳。」；下載區「桌面 App 本身不含遙測，程式碼與依賴不主動對外連線。它使用的 Microsoft Edge WebView2 是微軟的元件，可能有自己的網路活動，不在這個保證範圍內。」（WebView2 的例外是我加的：Calendar 票 024 觀察到 WebView2 有對外連線，只寫「無遙測」會超出 Calendar 已驗證的範圍，NFR-03c 也要求揭露；措辭請專案擁有者確認。）

## 產品規則與體驗

正常體驗：首頁先呈現可操作的試用，再往下呈現說明與下載。試用以拖曳為主，不需輸入時間數字。頁面一律誠實標示：試用是瀏覽器版、下載的是 Windows 桌面版、安裝檔未簽章。
