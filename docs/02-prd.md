## 使用者、工作與情境

主要使用者：想把時間看得見、不想輸入時間數字的人，首發為台灣使用者，在桌機瀏覽器上看到 Juicy 的網站（對應 G-06、G-01）。目前卡在：Juicy Calendar 只有 GitHub 原始碼庫與英文 README，一般人沒辦法在安裝前知道它用起來如何。（此痛點只有擁有者的陳述與 README 觀察，見 Brief A-01、A-02。）

主流程：進入首頁 → 先看到試用區 → 選一顆球、拖到日曆、調整長度、雙擊命名 → 看到命名好的區塊 → 往下看到下載區 → 點「下載 Windows 版」。

主要失敗與取消：球拖到日曆外放開、或拖曳中按 Escape，不建立區塊。違反時間規則（超出 10:00–15:00、長度不足 30 分鐘、名稱空白）的操作不會生效，區塊維持操作前的狀態，試用區的固定狀態文字區會用文字說明原因。試用內容不上傳，也不保存：重新整理頁面，試用內容就消失，日曆回到空的狀態。

## 故事與驗收條件

### US-01 不安裝，先在網頁上試用排時間（G-06）

身為想把時間看得見的訪客，我想在網頁上直接拖曳色球排時間、調整與移動區塊，以便不必先安裝，就知道它用起來如何。

- **AC-01.1（成功，畫面回饋）**：Given 訪客在可互動的環境（見 AC-01.6）開啟首頁，試用區可見，側邊有三種球（專注／藍、休息／綠、雜事／橘，每顆都有文字名稱），日曆為空且只顯示 10:00–15:00 When 把一顆球拖到某一天的 10:30 放開，再把該區塊的下緣拖到 13:00，再雙擊區塊輸入「寫 PRD」並按 Enter Then 該天出現 10:30–13:00、名稱為「寫 PRD」的區塊，顏色與球相同，球仍留在側邊可再次使用，且全程沒有在任何欄位輸入時間數字。（規則：建立、移動、調整長度都以 30 分鐘為單位；新區塊放下時長度為 120 分鐘，這個例子放下時為 10:30–12:30，之後才調整成 10:30–13:00。專案擁有者 2026-11-09 決定；其中 120 分鐘依 Calendar 既有行為，放進網頁後尚未驗證。）
- **AC-01.2（取消，不產生副作用）**：Given 訪客正在拖曳一顆球 When 在日曆以外的地方放開，或按下 Escape Then 不建立任何區塊，日曆上的區塊數不變。（依 Calendar AC-01.2。這兩種取消是否也要在狀態文字區顯示原因，PRD 尚未規定，見待決 Q-05。）
- **AC-01.3（拒絕，不產生副作用，說明原因）**：Given 可互動的試用區，日曆上有區塊 When 進行下列任何一種無效操作 Then 操作**不生效**：新建則不建立區塊；移動或調整長度則恢復操作前的位置與長度；不會自動截斷或修正時間。同時，試用區固定的**狀態文字區**用文字顯示這次被拒絕的具體原因（不只用顏色提示），中英文訊息一一對應。各情境：
  - (a) 新建超出：把球拖到 13:30 放開（120 分鐘區塊會到 15:30）→ 不建立區塊，顯示超出 10:00–15:00 的原因。
  - (b) 調整超出：把 10:30–13:00 的區塊下緣拖到 15:30 → 恢復 10:30–13:00，顯示超出時間窗的原因。
  - (c) 長度不足：把 10:00–10:30（30 分鐘）的區塊下緣拖到 10:00 → 終點不晚於起點，恢復 10:00–10:30，顯示長度不足 30 分鐘的原因。
  - (d) 移動超出：把 10:00–12:00 的區塊拖到 13:30 放開（會到 15:30）→ 恢復 10:00–12:00，顯示超出時間窗的原因。
  - (e) 名稱空白：名稱為「寫 PRD」的區塊清空名稱（或只剩空白）並按 Enter → 保持原名稱「寫 PRD」，顯示名稱不可空白的原因。
  
  （專案擁有者 2026-11-09 核准：把原本「不顯示訊息」的名稱拒絕，改為與其他無效操作一致的規則；訊息的確切文字、顯示多久見待決 Q-05。）
- **AC-01.4（不持久、不外送，查看結果）**：Given 訪客在試用區建立了 3 個有名稱的區塊 When 重新整理頁面 Then 日曆回到空的狀態、沒有任何區塊，球仍在側邊可用；同一個瀏覽器的另一個分頁不會看到這 3 個區塊（試用資料只屬於目前的分頁，分頁之間不共享）。並且 Given 訪客在試用區建立或修改區塊 When 以瀏覽器開發者工具的網路面板檢查 Then 沒有任何請求攜帶區塊內容（名稱、時間），且試用區附近有一句說明：試用內容不會上傳，重新整理頁面就會消失。（本條併入原 AC-01.5；編號不重用。）
- **AC-01.6（靜態預覽，不產生副作用）**：Given 訪客的瀏覽器主要輸入不同時符合 `pointer: fine` 與 `hover: hover`（判定只看這兩項，不看裝置名稱、作業系統或螢幕寬度） When 查看試用區 Then 看不到可操作的試用，改看到一張不能拖曳或點擊的圖片：實際試用介面的截圖，包含 10:00–15:00 的日曆、三種球，以及一個已放好的 10:00–12:00 區塊；圖下文字為「將球拖進日曆，即可建立時間區塊。請使用電腦及滑鼠體驗互動試用。」；圖片標示為產品預覽。圖與說明都有中文與英文兩版，隨網站語言切換，圖片的替代文字與圖下說明同步切換。此環境下不建立區塊、不產生任何資料；Windows 下載區照常顯示。邊界例子：同一台桌機接滑鼠，把視窗縮到手機寬度，仍然可互動（不看寬度）；只有觸控的手機顯示靜態預覽。（專案擁有者 2026-11-09 核准。英文版圖下文字尚待定。動態更換輸入裝置時是否重新判定，PRD 尚未規定，見待決 Q-03。）
- **AC-01.7（成功，移動既有區塊）**：Given 日曆上有一個 10:00–12:00 的區塊 When 把下緣拖到 10:30（縮成 10:00–10:30，30 分鐘），再把整個區塊拖到 14:30 放開 Then 區塊位於 14:30–15:00，長度仍為 30 分鐘，完整在時間窗內。（規則：「最晚起始 13:00」只適用新建，不適用移動既有區塊；專案擁有者 2026-11-09 核准。）

### US-02 試用後，能找到並下載 Windows 版，且知道限制（G-01、G-02）

身為試用過的訪客，我想在同一頁找到下載，並先看到系統需求與警告說明，以便安心安裝。

- **AC-02.1（成功，畫面回饋）**：Given 訪客在首頁（macOS、Linux 或 Windows 的瀏覽器看到的下載區相同，都是 Windows 下載），試用區在上、下載區在下 When 捲動到下載區並點「下載 Windows 版」 Then 瀏覽器前往 Juicy Calendar 的 GitHub Releases 最新版本頁；免安裝 .zip 與原始碼連結也在下載區內；從開啟首頁到抵達該頁，點擊不超過兩次。
- **AC-02.2（查看結果）**：Given 訪客在下載區 When 閱讀 Then 看到：僅支援 Windows 10 1803 以上 64 位元、需要 WebView2 執行階段、安裝檔未簽章所以 SmartScreen 會警告以及如何繼續、網頁試用為瀏覽器版（與桌面版的差異），以及桌面 App 離線、無帳號；每一項敘述都能對到 Calendar 文件中的來源，沒有未驗證的功能宣稱。

### US-03 用我的語言看，且不被追蹤（G-03、G-04）

身為台灣的訪客，我想看到繁體中文頁面，並確定網站不會追蹤我，以便放心使用。

- **AC-03.1（成功，畫面回饋）**：Given 訪客沒有手動選過語言，瀏覽器語言為繁體或簡體中文（任何中文地區，例如 zh-TW、zh-HK、zh-CN） When 開啟首頁 Then 顯示繁體中文；瀏覽器語言為不支援的語言（例如 ja）則顯示英文。當訪客手動切換語言後，所有文字（含試用區介面文字、狀態文字區訊息、靜態預覽圖與說明）立即變成所選語言，沒有殘留另一種語言或漏譯；重新整理頁面後，仍維持所選語言，試用資料不因此保留。訪客清除網站資料後，回到依瀏覽器語言決定。（專案擁有者 2026-11-09 核准。瀏覽器語言有多個候選時取哪一個，尚未規定，見待決 Q-08。）
- **AC-03.2（隱私，可查詢結果）**：Given 頁面已部署到測試環境 When 檢查頁面載入的網路請求與 cookie Then 沒有跨站追蹤、沒有識別個人的 cookie、沒有廣告請求；頁面上明講網站使用哪種流量統計、收集什麼（含語言偏好存在訪客自己的瀏覽器），並說明桌面 App 本身離線、無遙測。
