## 規格誤解

### PRD AC-01.7「起點靠近 12:30 刻度線」

「靠近」沒有說明是指標還是區塊起點，也沒有抓取偏移的算法。改為明確算例：10:00–12:00 的區塊、抓取偏移 20 分鐘、指標放開於 12:50 → 12:30–14:30，長度不變。

### 「資料沒變」要比對什麼

早期草稿要求操作後與操作前快照「全部相同」，連選取、焦點、編輯狀態都包含；但這些狀態的行為規格沒有定義（例如雙擊進入命名會選取該區塊，是基準程式碼的行為，不是規格）。改為：嚴格比對事件內容、`pastLength`、`futureLength` 與重做後結果；其餘列為觀察項，只記錄、不新增不變量。

### 「DOM 中不存在 `data-testid`」

只檢查某個 `data-testid` 不存在，不能證明控制項沒有被渲染（元素可能仍在 DOM，只是換了 id 或被隱藏）。改為以角色與可及名稱查詢為 0、不存在於 DOM（不是 `hidden`／`display:none`／`aria-hidden`／離螢幕／`disabled` 的殘留）、Tab 走訪不含這些項目。

## 踩過的坑

- Calendar 的 repository 位置依機器而異：這台機器是 `D:\Project\Fun\juicy-calendar\juicy-calendar`（外層資料夾不是 git repository；同層另有 `juicy-calendar-oneshotted-demo`，沒有基準 commit）。HANDOFF 寫的是 `..\juicy-calendar`。讀取前先用 `git cat-file -t <基準 commit>` 確認。
- Calendar 的命名輸入欄沒有 `maxLength`，UI 可輸入 31 字，由提交時的規則拒絕；超長名稱的測試走一般使用者路徑，不需要繞過 UI。
- Playwright 模擬 `pointer`／`hover` 的能力尚未驗證；動態切換資格改用注入假 `matchMedia` 的整合測試，觸控環境由實機（M-4）補。
- `Intl.Segmenter` 對 ZWJ 序列（如家庭 emoji）在各瀏覽器的結果可能不同【未驗證】，各瀏覽器結果記在 M-2。
