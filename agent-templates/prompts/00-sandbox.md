# 探索沙盒：從模糊想法到簡版 PRD

在**獨立的練習資料夾**做（例如 `sandbox/idea-v1/`、`sandbox/idea-v2/`），不要放進正式專案，避免正式規格干擾。
比較兩版時固定：同樣的時間、工具、模型；記下每次新增了什麼輸入。

## S1｜唯讀認識資料夾
```text
只讀目前資料夾，告訴我已有什麼、怎麼在瀏覽器或終端機開啟。這是獨立練習，不是正式專案；不修改檔案，不讀其他專案資料。
```

## S2｜一次提示做出第一版
```text
請直接完成我接下來貼的題目，使用目前這個獨立資料夾。遵守題目附的素材、時間與驗收要求；不要只寫計畫。允許你自行執行與修正，未驗證的事項如實回報。
```

## S3｜補上下文，做第二版比較
```text
在另一個新資料夾做同一題，沿用相同時間、工具與模型。這次新增的參考圖、素材與明確限制：＜填入＞。不要讀第一版的原始碼。
完成後與第一版用相同條件比較，並記下這次改變了哪些輸入。
```

## S4｜只修一個問題
```text
我看到：＜實際畫面或重現步驟＞。我期待：＜可觀察的結果＞。
先找出差異與原因，再只修這一件事。實際開啟並驗證；沒有瀏覽器工具就列出我要操作的步驟，不假裝已通過。
```

## S5｜列出 AI 自作主張的假設
```text
列出這次成果裡我沒有明確指定、由你自行決定的事項。每項附畫面或檔案依據，讓我選擇保留、修改或不做。
這一步只討論，不修改檔案；等我確認後才整理 PRD。
```

## S6｜收斂成簡版 PRD
```text
根據剛才已確認的決策，在目前資料夾寫出 prd.md。
包含：目標使用者、問題、核心流程、這次做與不做的範圍、至少三條 Given/When/Then 驗收條件（至少一條失敗情境）、待決事項。
不補未確認的需求，不寫程式，不畫流程圖。
```

> 出口：簡版 PRD 確認後，才把題目搬進正式專案，從 [01-stages.md](01-stages.md) 的 A 卡開始。
