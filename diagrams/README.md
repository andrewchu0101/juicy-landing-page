## 怎麼讀

- 顏色的意義：**紅框**是 SRS 已定義的規則判定；**綠框**是頁面內的處理（瀏覽器內，沒有後端）；**藍框**是使用者看到的畫面；**橘色**是待決。
- 「EX」虛線泳道是取消或無效操作，這些操作**不生效**：新建不建立；移動或調整恢復操作前的狀態；不自動截斷或修正。
- 圖例中的「頁面內的處理」其實對應 archify 的 `backend` 類型。那只是配色類別名稱，圖中沒有後端、API 或資料庫。
- 每張圖下方的卡片列出該圖用到的 SRS 邊界例子。

## 審圖時請特別注意（我發現的問題，未改 SRS）

1. **取整與「對齊」的關係有歧義。** FR-02 寫「起點在 10:00 到 13:00 之間**且對齊 30 分鐘單位** → 建立」，字面上像是「沒對齊就無效」；但規則字典把「指標怎麼對到單位」列為未決（OR-01），也就是可能是「取整」而不是「拒絕」。圖 02、03、04 把它畫成判定前的一個待決節點，**取整發生在判定之前**是我的假設，SRS 並未規定順序。
2. **區塊操作途中取消沒有定義。** FR-06 只涵蓋拖「球」時放在日曆外或按 Escape。拖曳移動或調整區塊途中按 Escape、或在日曆外放開，SRS 沒寫（Calendar 有類似行為，但本專案未採用），所以圖 03、04 沒有這個分支。
3. **命名時按 Escape 或點到別處沒有定義**，圖 05 沒有畫（卡片中有註記）。
4. **「拖曳邊緣」是否包含上緣。** FR-03 寫「邊緣」，AC 只有下緣的例子，但規則字典有「調整起點到 09:30 無效」，暗示上緣也可拖。圖 03 的卡片採用了字典的例子。
5. **全站隱私不符合時的處理沒有定義。** FR-07 的檢查是上線前的驗證準則（NFR-01），不是執行期流程，圖 06 只畫符合時的結果。

- 圖的來源是 `src/*.workflow.json`（archify workflow schema v2，`meta.locale` 為 `zh-TW`）。HTML 由來源檔產生，不要直接改 HTML。
- 重建單張圖（在專案根目錄執行；`<archify>` 是 archify 技能的安裝路徑，目前為 `C:/Users/student/.claude/skills/archify`）：

```bash
node <archify>/bin/archify.mjs finalize workflow diagrams/src/<名稱>.workflow.json diagrams/<名稱>.html \
  --quality showcase --out-dir diagrams/evidence/<編號> --json
```

- 驗證紀錄見 `verification.md`，各圖的收據與截圖在 `evidence/`。
