# HANDOFF —— ＜專案名稱＞ 交接紀錄

> 複製到 `docs/HANDOFF.md`。換人、換工具、換對話、或今天收工時更新**最上方摘要**；下面保留舊紀錄不刪。
> 💡 寫給「完全沒看過這段對話的人」。只寫查得到的事實，不寫印象；證據附指令或路徑。
> 💡 與 `CURRENT_STATUS.md` 分工：這份記「這一輪做到哪、下一步」；CURRENT_STATUS 記「整個專案現在是什麼狀態」，只在里程碑改變時才動。

## 摘要（每次覆寫這一段）

| 項目 | 內容 |
|---|---|
| 更新時間 | ＜YYYY-MM-DD HH:MM＞ |
| 目前目標 | ＜一句話＞ |
| 工作目錄 | ＜絕對路徑＞ |
| 分支／HEAD | ＜分支名＞ ／ ＜短 SHA＞（不是 git repo 寫「不適用」） |
| 工作樹 | ＜乾淨／有未提交修改：列路徑＞ |

### 已完成
- ＜成果＞ —— 證據：＜指令與結果／檔案路徑＞

### 進行中
- ＜做到哪、卡在哪＞

### 阻塞
- ＜缺什麼、等誰、期限＞（沒有就寫「無」）

### 下一步（最多三項）
1. ＜最先做的事，附需要讀的檔案＞
2. ＜＞
3. ＜＞

相關 issue／PR：＜連結或「無」＞

### 狀態核對（分開寫，不要混為一談）

| 面向 | 狀態 | 說明 |
|---|---|---|
| 已實作 | ＜是／否／部分＞ | |
| 自動測試 | ＜Passed／Failed／Skipped／Blocked／Not Run＞ | 指令：＜＞ ／ 環境：＜＞ |

### 接手者要先知道
- ＜已確認的決策、不要重做的事、容易踩的坑；沒有就刪除這段＞
