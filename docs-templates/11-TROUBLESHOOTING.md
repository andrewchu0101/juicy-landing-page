# 卡關了，先找症狀

> 通則：**先停、先保留證據、再選下一步。** 證據 = 重現步驟 + 完整指令 + 實際輸出 + 對應的規格段落。
> 做完一步就重新驗證；不要在還沒讀 `git diff` 前執行 `git restore`、`git reset --hard`、`git clean`。

| 症狀 | 先做 | 不要做 |
|---|---|---|
| **A. AI 越改越糟** | 停下，保存 `git diff` 與重現步驟；已有可確認的成果先以**明確路徑**存一個版本。新對話指定讀工單、規格、LESSONS；原因不明改用 `diagnosing-bugs`。 | 不讀 diff 就還原；繼續在同一個混亂的對話裡補救。 |
| **B. 做出來不是我要的** | 找出實際行為和 AC 的差異。規格漏寫或矛盾 → 請人決定；文件對、實作偏 → 才修實作。決策寫回承載它的文件。 | 改規格去配合程式。 |
| **C. AI 說完成，但不能跑** | 自己依 README 啟動並跑測試；要求貼出實際輸出和「未驗證清單」。 | 相信「應該可以」。 |
| **D. 測試紅燈修不好** | 先分類：環境、規格、測試、實作哪一種。保留完整命令與輸出，一次只驗一個原因。 | 放寬 assert、刪測試、重跑到綠。 |
| **E. 改了一堆無關檔案** | 對照工單與 diff，保留相關修改；無關修改由人決定是否還原。 | `git add .`／`git add -A`；直接清空工作目錄。 |
| **F. 忘記之前的決策** | 確認決策是否已寫進 `docs/` 或 `AGENTS.md`；新對話明確指定讀取。換階段前先寫檔；換人用 `handoff`。 | 指望對話記憶或 agent 私人記憶。 |
| **G. 網頁開了但操作失敗** | 記錄操作步驟、Console／Network 錯誤、API 回應；先重現再修。沒有瀏覽器工具就列出步驟由人操作。 | 宣稱「自動檢查通過」。 |
| **H. App 或測試起不來** | 核對語言版本、虛擬環境、安裝路徑、port；用專案虛擬環境的明確路徑執行。 | 全域安裝套件；盲目終止不明程序（換 port 即可）。 |
| **I. 進度落後或需要回到已知好狀態** | 見下方「救援流程」。 | 刪掉分支重建；沒 fetch 就切。 |
| **J. 工具／MCP／圖表工具失敗** | 保留真實錯誤訊息；不同 agent、不同平台各自驗證。圖表工具壞了就改用 Mermaid；MCP 沒通就由人操作或查官方文件。 | 以「設定檔存在」宣稱已接通。 |
| **K. hook 沒擋住／一直誤擋** | 確認 `jq` 在 PATH（沒有 jq 時 guard 會靜默放行）；用 `.maintain/check.sh` 跑回歸測試。 | 用 `--no-verify` 繞過。 |

## 救援流程：先存進度，再切快照

1. `git status`、`git diff` —— 看清楚有什麼。
2. 把**本次成果**用明確路徑 `git add <路徑>` 後 commit（不用 `git add .`；資料庫、`.env`、金鑰不加）。
3. 確認工作樹乾淨，停止開發伺服器。
4. `git fetch <遠端>`，再 `git show-ref --verify refs/remotes/<遠端>/<分支>` 確認目標分支**真的存在**；不存在就停下來問人。
5. `git switch -c rescue-<名稱> <遠端>/<分支>` —— 開新分支，**不覆蓋、不刪除**原本的分支。`rescue-<名稱>` 已存在時，先看它的進度，不要刪掉重建。
6. 切過去之後：重建虛擬環境與依賴；資料庫不會隨 Git 分支變動，要自己重建。先讀快照與自己進度的差異，再繼續。
